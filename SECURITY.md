# Security Policy

## Supported Versions

AlgoLens is actively maintained, and security fixes are prioritized for the latest stable release.

| Version | Supported |
| ------- | --------- |
| Latest stable release | :white_check_mark: |
| Older releases | :x: |

Users are encouraged to update to the latest available version of AlgoLens to receive security fixes and improvements.

## Reporting a Vulnerability

The security of AlgoLens and its users is important. If you discover a potential security vulnerability, please report it responsibly.

### How to Report

- **Preferred method:** Use [GitHub's private vulnerability reporting](https://github.com/Garv3068/AlgoLens/security/advisories/new) to submit a report confidentially, if the feature is enabled for this repository.
- **Alternative method:** If private vulnerability reporting is unavailable, contact the repository owner through their GitHub profile: [Garv3068](https://github.com/Garv3068).

Please avoid disclosing security vulnerabilities publicly until they have been investigated and, where applicable, addressed.

### What to Include

To help us investigate the issue, please include:

- A clear description of the vulnerability.
- Steps to reproduce the issue.
- The potential impact and affected components or versions.
- Screenshots, logs, or a proof of concept, if available.
- Any suggested mitigation or fix, if known.

Please do not include real credentials, private user data, or other sensitive information in your report.

### Response and Resolution

- **Acknowledgment:** We aim to acknowledge vulnerability reports within 7 days.
- **Investigation:** We will assess the report, determine its severity, and investigate its potential impact.
- **Updates:** We will provide updates as reasonably possible while the issue is being investigated.
- **Resolution:** If the vulnerability is confirmed, we will work toward an appropriate fix and release a security update where necessary.
- **Declined reports:** If a report is not considered a security vulnerability or cannot be reproduced, we will explain the reasoning when reasonably possible.

Resolution times may vary depending on the severity, complexity, and reproducibility of the issue.

### Scope

Security reports may cover issues such as:

- Unauthorized access to user data or browser resources.
- Unsafe handling or execution of code.
- Cross-site scripting (XSS) or other injection vulnerabilities.
- Exposure of sensitive information.
- Insecure permissions or unintended browser-extension behavior.
- Vulnerabilities in dependencies or third-party integrations used by AlgoLens.

Reports should relate to AlgoLens itself or to a security issue directly caused by its functionality.

### Responsible Disclosure

Please act in good faith when researching and reporting vulnerabilities. Do not exploit vulnerabilities beyond what is necessary to demonstrate the issue, access other users' data, disrupt services, or publicly disclose an unresolved vulnerability without giving us a reasonable opportunity to investigate.

We appreciate the time and effort of security researchers who help make AlgoLens safer.

Thank you for helping improve the security and reliability of AlgoLens.
